# HX4S20C HDMI 多媒体播放系统

全国大学生嵌入式芯片与系统设计竞赛 · 2026 · FPGA 创新设计赛道 · **选题一**
平台：安路 **HX4S20C**（EG4S20BG256，19,600 LUT/FF，片内 2M×32bit SDRAM，4 个 PLL）。
**全部 RTL 自研**：HDMI 发送端从 TMDS 编码到四路串化、SDRAM 控制器、SD 协议栈、视频时序全部自己写，
不使用厂商加密 HDL（官方样例的 `sdr_as_ram` 等三个加密文件也没用）。

**M5 画面偏移：已闭环。** 现象曾是：图片能显示，但整幅图侧移/纵移若干像素（并沿行回绕出第二份），
每次复位偏移量和方向都不同。根因是**读通路的行走与显示的帧边界没有对齐**——它连续走画面，而"画面接管
屏幕"发生在显示的帧边界，接管那一瞬间它可能正处在某一行中间或任意一行。做法：接管前把读通路**重启**
（`mm_frame_rd` 的 `restart`），让它回到画面第一个字并**阻塞到显示的下一个帧边界**才开始走、缓冲在
这一帧里灌满，再让画面接管；接管决策在帧边界**前一个**消隐像素上做（`frame_next`），所以帧的第一个
像素就已经是画面的。板上多次复位无偏移。细节与"已否掉的写法"见 `doc/路线图.md` 第 3 节。

**M6 交互**：8 张图按槽位装进帧存（一天一张，`base_i = i × 230400` 字），槽位 0 先装好就上屏，
其余在后台继续装（读走突发口、写走单字口）。**KEY2（板载按键，引脚 B2）= 切下一张；
SW1（拨码开关，引脚 C8，拨上为 1）= 自动轮播（1 秒一张）**。KEY1（A2）仍是复位。
引脚来源：`doc/参考-官方/HX4S20开发板手册-HDL版2410.pdf` 第 15/16 节（同目录 `pin.adc` 一致）。

## 3. 怎么编译、下载、自检

1. TD 6.2.1 打开 `prj/hdmi_player.al`，顶层 `top`，Synthesis → Physical Design → Download，
   HDMI 线接开发板 **HDMI_B**。
2. **不用开 GUI 的命令行流程**：先在 `prj/hdmi_player_Runs/syn_1`、再在 `.../phy_1` 执行
   `E:\TD621\bin\td_commands_prompt.exe E:/TD621/scripts/DefaultFlow.tcl`
   （脚本路径**要用正斜杠**，反斜杠会被 Tcl 吞掉）。注意日志文件名是 **`td_<时间戳>.log`**，
   `run.log` 是 GUI 留下的旧文件，别 grep 错。
3. 本地自检：`pwsh -File sim/check_syntax.ps1`（只编语法）、`pwsh -File sim/run_sim.ps1`（跑全部自检，
   每个测试台末尾打印 `RESULT: PASS/FAIL`）。
4. 上板前必看：布局布线的 `SWNS`/`HWNS` **都要为正**（本工程余量一直很薄，只有 +0.8 ns 量级）。

## 4. TF 卡怎么准备

图片必须是 **640×480、24 位、非压缩 BMP**，而且**必须用工具顺序写入**：

```
python tools/write_card.py --no-audio --dry-run     # 先看写入计划（含顺序与 LBA）
python tools/write_card.py --no-audio               # 确认后真写
```

FPGA **不解析文件系统**：它逐个扇区看头两个字节是不是 `BM`，所以手动拖图片、手动删图片都不行
（旧数据的物理扇区还在，照样会被扫到）。工具默认盘符是本机固定的 `G:`，并带盘符安全闸：
只有"盘符 = `G:` 且容量 ≤ 64 GB"的卷才肯写，`--yes` 也绕不过（必须显式 `--force-drive`）。

## 5. 上板指示：6 位数码管

```
 d5  d4  d3  d2  d1  d0
状态 场景 图数 错误 心跳 帧数
```

- **d1** = 50 MHz 主时钟心跳，0.25 s 一步；**d0** = 像素域帧计数，1 s 一步。
  **d1 在跳而 d0 停在某处 = 像素域没出帧**——这是最快分域判据。
- **d5** = `2` 像素域在出帧 / `E` 没出帧。
- d4 d3 d2 每 2 秒轮翻，共 **19 页**（页 16 已退役，轮翻跳过）：

| 页 | d4 | d3 | d2 |
|---|---|---|---|
| 0 | 阶段码（见下） | 找到的图片张数 | 错误码（见下） |
| 1 | 加载器**真读**了几个扇区（640×480 应为 `709`） | | |
| 2 | `A`（MBR 校验通过） | 分区容量 GiB | |
| 3 | 加载阶段码 | 加载器错误码 | 交出的前 255 个像素字节里 `0xFF` 的个数（高 4 位） |
| 4/5/6 | 自检探针写进去的 `A5A5_5A5A` 读回来的**原始值**（页 6 的 d2 = 能整字读回的采样码） | | |
| 7 | `A` = 突发端口交出的第一个字就是所问的字 | 错位字距 | 能把突发对齐的采样偏移 |
| 8 | `A` = 回环（读回控制器自己驱动的值） | 打包 FIFO 溢出计数 | 读通路像素下溢（高字节） |
| 9/10 | 画面区第 0 个字 = 文件第一个像素的 R,G,B（6 个 nibble） | | |
| 11/12 | 画面区第 229920 个字 = 屏幕第一行最左那个像素 | | |
| 13 | 读通路**收到的字**的变化数 ÷256（`0F`~`10` = 每个字都不同；`00` = 一直同一个） | 低位 | `A` = 最近 0.25 s 凑满过 4096 字窗口（字还在到）/ `F` = 字停了 |
| 14 | 加载器被指到的起始扇区（LBA **÷16**，一张图 = `70`） | | |
| 15 | 当前屏上的图号（0~7） | 已经装好的张数 | 自动轮播开关（`1` = SW1 拨上） |
| 17 | `vout_rgb` 在最近 1024 个有效像素里的变化数（实时）：几百 = 正在出画面，`000` = 线上恒定 | | |
| 18 | 读通路已经走过的存储行数（实时，应一直跳） | | |
| 19 | 读通路字缓冲用量 ÷16（`00` 空 … `10` 满） | 低位 | {状态机, 是否允许取数, 突发忙}：状态 0=空闲 / 1=等突发数据 / 2=冲刷中 |

**页 0 的 d4 阶段码**：0 未开始 / 1 等卡上电 / 2 CMD0 / 3 CMD8 / 5 ACMD41 轮询 / 6 CMD58 /
7 初始化完成 / 8 CMD17 已发 / 9 等数据 / A MBR 通过 / B 扫描中 / C 扫描完成 / F 失败。
**页 0 的 d2 错误码**：1 无 R1 / 2 R1 带错 / 3 无 `0xFE` / 4 数据错令牌 / 5 尾部非 `55AA` /
6 没扫到图 / 7 初始化失败。
**页 3 的 d4 加载阶段**：0 未开始 / 1 逐扇区读 / 2 等写通路收尾 / 3 完成 / F 失败（每秒自动重试）。

## 6. 三个必须知道的坑（都真栽过）

1. **新增 RTL 文件后要确认它进了 TD 的文件列表**。TD 会用自己的内存列表覆盖
   `prj/hdmi_player.al`，所以手动改 `.al` 只在 TD 关着时有效；而**命令行流程认的不是 `.al`**，
   是 `syn_1`/`phy_1` 里的 `.prj` 快照，两份都要改。症状：综合报 `xxx is a black box`。
2. **综合日志的 WARNING 要当回事，而且要看整份**。`HDL-5007 literal value 'd16 truncated to fit
   in 4 bits`（`4'd16` 写进 4 位寄存器 → 截断成 0）曾让数码管永远停在页 0；这类警告出现在
   日志**前段**，用 `Select-Object -Last N` 会漏掉。同类前科：`3'd8` 被截断成 0，状态机把"完成"当"等待"。
3. **布局布线跑完要看 `SWNS`/`HWNS`，不能只看 "bitgen complete"**。时序没收敛照样生成 bit 文件，
   上板表现是随机花屏或偶发错像素——最难查的那一类。
