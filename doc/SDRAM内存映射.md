# SDRAM 内存映射与容量核算

片内 SDRAM（型号 EM638325，与 FPGA 3D 合封）：

```
容量      2M × 32bit = 2,097,152 字 = 8,388,608 字节 = 8 MiB
物理组织  4 bank × 2048 行 × 256 列 × 32bit
地址宽度  21 位字地址（与官方样例 global_def.v 的 ADDR_WIDTH 一致）
```

---

## 1. 分配表

| 区域 | 每项字节 | 每项字数 | 数量 | 合计字节 | 合计字数 |
|---|---|---|---|---|---|
| 图片帧缓存（8 张，24 位紧凑） | 921,600 | 230,400 | 8 | 7,372,800 | 1,843,200 |
| 音频环形缓冲 | 262,144 | 65,536 | 1 | 262,144 | 65,536 |
| **合计占用** | | | | **7,634,944** | **1,908,736** |
| 剩余 | | | | 753,664（0.719 MiB） | 188,416 |
| 利用率 | | | | **91.0%** | |

**结论：不会溢出，余 0.72 MiB。**

### 帧缓存基地址

```
base_i = i × 230,400 字 = (i × 225) << 10        i = 0..7
```

225 = 128 + 64 + 32 + 1，用几个加法和移位就能算，不需要乘法器。

每张图 230,400 字，正好是 1024 字的整数倍（230,400 = 1024 × 225），
所以每张图的起始位置都落在行组边界上，行命中率高。

---

## 2. 为什么必须用 24 位紧凑存储

| 存储格式 | 每张占用 | 8 张合计 | 占 8 MiB | 单 SDRAM 最多放几张 |
|---|---|---|---|---|
| 32 位/像素（样例做法，24 位有效 + 8 位填充） | 1,228,800 B | 9,830,400 B | **117.2%** | 6 张 |
| **24 位/像素（紧凑）** | 921,600 B | 7,372,800 B | **87.9%** | 9 张 |
| 16 位/像素（RGB565） | 614,400 B | 4,915,200 B | 58.6% | 13 张 |

带 256 KB 音频缓冲时，图片上限是 8 张：9 张需要
2,073,600 + 65,536 = 2,139,136 字 > 2,097,152 字。

### 24 位紧凑存储为什么干净

```
每行  640 × 3 = 1920 字节 = 480 个 32 位字     ← 整行对齐
每张  480 行 × 480 字 = 230,400 字              ← 整除
相位  每 8 个像素 = 24 字节 = 6 个字             ← 打包相位每行归零
```

如果每行不是整数个字，就得跨行维护字节相位。这里每行正好 480 字，
写路径（SPI 字节流 → 3 存 4）和读路径（字 → 3 字节/像素）都能每行复位相位。

## 3. 余量敏感性

| 配置 | SDRAM 占用 | 结论 |
|---|---|---|
| 8 图 + 256 KB 音频（当前方案） | 91.0% | 通过，余 0.72 MiB |
| 8 图 + 512 KB 音频 | 93.7% | 通过，余 0.53 MiB |
| 8 图 + 1 MiB 音频 | 100.4% | **溢出** |
| 9 图 + 256 KB 音频 | 102.0% | **溢出**（超 0.16 MiB） |
| 7 图 + 256 KB 音频 | 80.0% | 通过，余 1.6 MiB |

（上表数字由脚本核算，不是估算：`8 图 24 位 + 256 KB 音频 = 1,908,736 字 / 2,097,152 字`。）

音频环形缓冲 256 KB 对应约 1.33 秒。实际需要多少？音轨数据率 192 KB/s，
SPI 读一个 512 字节扇区约 190 µs，即每 2.67 ms 需要一个扇区，读取占空比不足 8%。
缓冲只需要覆盖 SD 卡偶发的读延迟尖峰，几十毫秒量级即可，256 KB 已经相当宽裕。

## 4. 不占 SDRAM 的部分

以下都用片内 ERAM（64 块 9Kb + 16 块 32Kb = 136 KB），不参与上面的核算：

* 写/读方向上的跨时钟 FIFO
* BMP / 音轨头解析用的扇区暂存
* 后续的 OSD 字模、缩放行缓存

---

## 5. 如果以后想要更多场景

SDRAM 只限制**同时驻留**的张数，不限制卡上能放多少场景（每场景约 0.9 MB 图 + 音乐）。

要超过 8 个场景，有三条路：

1. 减小音频环形缓冲（收益很小，只省几百 KB）
2. 改成"驻留 N 张 + 切图时从卡现读"（切图会停顿，损失体验）
3. 降低分辨率或色深（画面质量下降）

当前 8 场景在选型上留了 0.72 MiB 余量，不需要动。
